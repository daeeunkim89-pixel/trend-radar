# BTP 편집·발송 기준 — 2026-11-12
이 사용자 최신 지시가 과거 매시간5개/08~23시/24~48시간 확장 지시보다 우선한다.

## 발송
PC와 무관한 기존 클라우드 예약에서 한국시간 08·11·14·17·20시, 매회 서로 다른 소재 10개를 한 메시지로 보낸다. 08시 시작 3시간 주기이며 21시는 운영 마감이다. 21시 별도 회차나 야간 발송을 추가하지 않는다. 실행 사이 종료하며 장시간 대기·자기호출·중복 예약은 하지 않는다. 사용자 게시 목표 하루10개와 추천50개는 다르다.

## 선정: 한국 독자가 지금 올릴 이유
- 스포츠가 중심이다. 한국 주요 선수·인기 종목, 주요 리그와 세계적 스타의 큰 결과, 우승·탈락·대회 판도 변화, 역사적 기록, 확정 이적·경질, 중대한 징계·사건을 우선한다. 공식 원본 발표와 실제 장면을 먼저 보고, 영상이 핵심일 때만 시청한다.
- 시사는 신문 첫 장급의 확정 변화로 한정한다. 한국 독자에게 직접 의미 있는 권력·제도·전쟁·경제·산업의 큰 변화, 큰 피해나 사회적 파장이 있는 사건을 비교한다. 해외 기사라는 이유나 금액이 크다는 이유만으로 뽑지 않는다.
- 기본 제외: 흔한 대표팀 발탁·경기 예고·훈련/단합 발언·일반 부상·사소한 포지션 변화, 미확정 감독/이적 후보설, 해외 중소 종목의 세부 기록, 통상적 합병심사/투자 계획/현지 날씨/지역 정치, 보통의 주가 등락·전망·관료 발언. 큰 새 사실과 한국 독자의 게시 이유가 분명한 예외만 검토한다.
- 일반 연예·팬덤·예능·근황·컴백·열애·무대 디테일은 탐색/추천하지 않는다. 사회·산업적으로 메이저한 사건만 시사에 포함한다.
- 국내 스포츠·리그/대회/구단/선수 공식 채널 → 국내 주요 스포츠 및 종합뉴스 → 주요 국제뉴스를 함께 본다. Reuters 한 곳에서 10개를 채우지 않는다. 다른 사이트에 실린 같은 통신사 기사도 독립 원본으로 세지 않는다. 스포츠 우선이지만 억지 고정 비율은 없다.
- 각 후보는 '새 사실 한 가지 / 인지도·파급력 / 지금 올릴 이유 / 바로 쓸 원문이나 실제 자료'가 있어야 한다. 중요도·새로움·게시 완성도로 1~10위를 정한다. 100만 조회수는 편집 목표이며 수치나 확률을 보장하지 않는다.

## 늦은 추천 금지
주간은 직전3시간에 처음 공개된 사실을 우선한다. 08시는 전날20시 이후 밤사이 새 소식을 먼저 본다. 부족할 때만 아직 뜨거운 미발송 대형 사실로 주간6시간/08시12시간까지 넓힌다. 24~48시간 전 소식을 수량 채우기로 재활용하지 않는다.
사건일, 최초 공개시각, 실제 확인시각을 구분한다. 재기사·재업로드·검토시각을 최초 공개시각으로 쓰지 않는다. 알려진 사건의 새 중대한 후속은 무엇이 바뀌었는지 명시한다. published_at은 실제 확인한 최초 공개시각이며 없으면 다른 출처로 확인한다. sender도 v2의 주간6시간/08시12시간 한도를 검사한다. 본문에 최초 공개 KST를 표시한다.
최근7일 sent/uncertain의 사실·event_key·원문·자료 및 확인 가능한 BTP 게시를 대조한다. 이름 자체는 제외어로 막지 않는다. 같은 사실의 제목 변경·다른 매체 재기사는 중복이다.

## 효율과 완료
새 review-inbox와 필요한 이력 필드만 읽는다. 첫 검색6/본문18에서 조사하고 미달이면 부족 분야만 검색2/본문7을 최대2회 보충한다(총 검색10/본문32). 한도는 목표가 아니며 10개 검증·중복 확인 즉시 종료한다. 시간 목표만으로 미달 종료하지 않는다. 사이트 목록·원문을 효율적으로 비교하고 차단 URL 반복·전체3000개 덤프·매회 설치/중복수집·병렬 에이전트는 하지 않는다.
제출 전 단일 표준라이브러리 edition_preflight.py로 잘못된 kind/필드/길이를 고친다. pick.kind는 article/official/community/social, major_news는 readiness.mode에만 쓴다. 버전2 picks와 버전4 trigger_commit 요청을 같은 커밋에 넣어 서버가 정확한 해시를 계산하게 한다. 예약이 수분 일찍 시작되면 해당 scheduled_for 회차로 제출하고 GitHub 서버만 최대5분 정시를 기다린다. AI는 정시 대기하지 않는다.
최종 비공개 중복 제외 뒤10개가 필요하다. 부족·실패·형식검사를 성공으로 쓰거나 약한 소식을 꾸며 채우지 않는다. 오류는 원문을 보고 안전하게 수정하며 sent/uncertain 잠금을 지우거나 재송신하지 않는다. 실제 stories=10/messages=1/missing=0/target_met=true와 전송 로그를 확인한다. 계정 전체 사용량이나 다음 실제 발송의 성공을 설정 저장만으로 보장하지 않는다.
