# BTP — 3시간마다 주요 소재 10개
[최신 편집·발송 기준](btp-news-policy-20261104.md)이 과거 모든 주기·수량·신선도·예산 지시보다 우선한다.

1. 기존 클라우드 예약은 KST08/11/14/17/20시. 21시 이후 없음. 회차10개를 한 메시지로 보내며 PC 전원과 무관하고 회차 사이 종료한다.
2. 스포츠의 큰 결과·확정 발표·중대 사건과 한국 독자에게 의미 있는 1면급 시사를 비교한다. 국내 스포츠/공식 원본과 주요 뉴스로 소스를 넓힌다. 해외 통상 합병심사·현지 날씨·단순 주가 등락·대표팀 단합 발언·발탁·일반 부상·후보설·일반 연예로 채우지 않는다.
3. 주간 직전3시간, 08시는 전날20시 이후 새 사실 우선. 미발송이며 현재성 있는 대형 사실만 주간6시간/08시12시간까지. 최초 공개와 사건일을 실제 원문에서 확인하고 published_at에 최초 공개시각을 기록한다. 24~48시간 된 소식의 재기사는 제외한다. 서버도 이 신선도를 검사한다.
4. 최근7일 sent/uncertain·event_key·URL·자료·동일 사실을 대조한다. 같은 사람의 실제 중대 후속은 새 사실을 명시한다. 발견용 목록은 검증된 추천이 아니다.
5. 새 inbox 재사용. 첫 검색6/본문18, 미달이면 검색2/본문7을 최대2회 추가(총10/32). 10개 완성 즉시 끝낸다. 전체 이력/3000개 후보/긴 테스트 로그 덤프·차단 URL 반복·매회 설치·병렬 에이전트·AI 정시대기는 금지한다.
6. [스키마와 승인 제출](btp-editorial.md)의 version2 picks를 edition_preflight.py 단일 파일로 비송신 검사한다. kind=article/official/community/social, readiness.mode=major_news/scene. 입력 오류를 고친 뒤 version4 요청 {"version":4,"hour_utc":"대상 UTC YYYYMMDDHH","binding":"trigger_commit"}와 같은 커밋에 원자 제출한다. 두 파일 동시 변경·회차 일치·ChatGPT 검토·10개가 필요하다. 서버가 불변 커밋의 정확한 바이트로 해시를 계산한다.
7. 예약 scheduled_for의 해당 승인 시각을 따른다. 수분 일찍 시작되면 GitHub에 즉시 제출하고 AI는 종료한다. GitHub sender만 최대5분 정시를 기다리며 더 이른 요청은 거부한다. 08/11/14/17/20 이외 과거 회차 재생은 금지한다.
8. BTP_REQUIRE_COMPLETE=1은 최종 비공개 중복 제외 후10개 미달을 needs_more_research로 남긴다. 추가 조사 예산을 남겨두고 미달을 성공으로 쓰지 않는다. 입력 오류는 진단을 보고 안전 재시도하며 sent/uncertain 잠금·전송 이력을 유지한다. 봇 토큰·Chat ID·암호화 state를 읽지 않는다.
9. 실제 Actions 전송 로그와 공개 stories=10/messages=1/missing=0/target_met=true를 짧게 확인한다. 별도 운영 보고·연결 테스트 Telegram·Instagram 자동 게시·새 예약은 만들지 않는다. 사용자가 별도 즉시 요청할 때만 version3 user_requested로 실제 현재 회차를 사용한다.
