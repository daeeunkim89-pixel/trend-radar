# BTP — 매시간 주요 소식 5개
[2026-11-04 최신 편집 기준](btp-news-policy-20261104.md)을 먼저 읽는다. 이 문서가 과거 아이돌·예능·자막·작은 팬 농담 중심 탐색, 매시간 누적 작업, 3시간마다10개와 10개 강제 조건보다 우선한다.

## 목적
스포츠 주요 뉴스를 중심으로 신문1면급 시사 대형 뉴스를 함께 추천한다. 연예는 사회/산업적으로 메이저한 사건일 때만 시사로 포함한다. 일반 연예·자컨·팬덤·예능·무대 디테일·사소한 농담·동네 사건·일반 판결로 채우지 않는다. 100만 조회수를 노릴 대중적 파급력이 목표이며 예측치나 보장은 만들지 않는다.

## 실행
한국시간08~23시 매 정시 클라우드에서5개를 한 메시지로 보낸다. 사용자의 게시 목표 하루10개와 추천 발송 매시간5개는 다르다. PC 전원과 무관하며 실행 사이에는 종료한다. 야간·중복 예약·Instagram 자동 게재·과거 회차 재생·테스트 송신은 금지한다.
2026-11-08 사용량 절약: GitHub 자동 수집이 만든 최신 review-inbox를 우선 재사용한다. 에이전트가 매회 설치·수집을 다시 하지 않는다. 수집 결과가 오래되면 신뢰할 수 있는 공식/주요 뉴스의 새 사실을 집중 검색한다. collector의 키워드 순위는 발견 보조이며 선정 승인이 아니다.
첫 조사는 검색최대4·원문최대8. 시간 목표만으로 5개 미달 상태에서 종료하지 않는다.5개 미달이면 검색2·원문4를 한 번만 추가한다(합계 검색6·원문12). 무제한 확장·자기호출·병렬 에이전트는 하지 않는다. 원문 확인과7일중복검사를 마친5개가 확보되면 즉시 제출한다. 예비를 불필요하게 늘리지 않는다. 한도를 줄인다고5개 미달을 성공으로 보고하거나 검증하지 않은 소재로 채우지 않는다.
도구 안에서 inbox 후보·발송 이력·상태를 필요한 필드로 요약하고 긴 과거 대화·전체3000후보·전체 테스트 로그를 모델에 출력하지 않는다. CI의 자동 검사는 유지하며 에이전트가 반복 실행하지 않는다. 계정 잔량은 실제 조회된 경우만 말하고, 프롬프트의 검색 상한을 계정 전체 사용량 보장으로 표현하지 않는다.
차단 URL 반복·인증 우회·영상 한 편에 고착·전체3000개 덤프·대형 과거 대화 반복·연결 테스트·정각까지 대기·장시간 완료 감시는 하지 않는다. 접근 가능한 공식 발표·독립 보도로 전환한다.

## 추천 완성
주요 스포츠 결과·확정 이적·감독 교체·역사적 기록·중대 징계/부상/논란, 정치·국제·경제·사회 대형 사건을 비교한다. 당사자 발표와 신뢰할 수 있는 원문 본문에서 핵심 새 사실·규모·영향·사건일을 확인한다. 확정 뉴스는 major_news 사실 카드로 충분하며 영상이 핵심일 때만 scene으로 실제 장면을 본다.
처음12시간 우선, 부족하면 미발송24/48시간까지 확장한다. 재기사/재업로드 시간을 원래 사건일로 바꾸지 않는다. generated_at과 verified_at은 실제 검토75분 안, 보지 않은 영상을 시청했다고 쓰지 않는다.
최근7일 sent/uncertain의 event_key·URL·자료·동일 사실과 실제 확인 가능한 BTP 게시를 대조한다. 인물 이름 전체를 검색 제외어로 막지 않는다. 새로운 중대한 후속은 새 사실을 명시하되 같은 사실의 제목 변경은 중복이다.
제목·왜 큰 뉴스인지·원문 링크를 짧게 제시한다. 상세 연예 디테일과 불필요하게 긴 제작 설명은 필요 없다.

## 제출과 완료
[검토본과 승인 발송 절차](btp-editorial.md)의 version2 스키마를 지킨다. 검증된5개를 우선 준비하고 중복 제외로 필요할 때만 위 조사 한도 안에서 예비를 확인한다. 정기 발송은 version2 picks와 version4 report-request {"version":4,"hour_utc":"실제 UTC YYYYMMDDHH","binding":"trigger_commit"}를 같은 커밋에 원자 제출한다. 에이전트는 SHA256을 추정하거나 수기로 쓰지 않는다. GitHub의 pin_report_request.py가 해당 불변 커밋의 정확한 picks 바이트에서 SHA256을 계산해 기존 version2 발송 요청으로 변환한다. 두 파일이 함께 바뀐 커밋, 일치하는 회차, ChatGPT 검토와 5개를 요구한다. 기존 발송기의 시간·신선도·스키마·비공개 중복 검사와 5개 강제 조건은 그대로 적용한다. 기존 version2/3의 해시가 틀렸다면 자동 수정하지 않고 거부한다. 기존 Python workflow만 사용하고 봇 토큰·Chat ID·암호화 state는 읽거나 출력하지 않는다.
production BTP_REQUIRE_COMPLETE=1은 검토 후와 최종 비공개 중복 제외 뒤5개 미달이면 exit3/needs_more_research로 반환한다. 이 경우 잠금을 완료하거나 현황을 성공 발송으로 쓰지 말고 실제 부족을 기록한다. 추가 조사는 남은 위 조사 한도 안에서만 한다. 예약은 사용자 중지 없이 끄지 않는다.10개를 요구하는 오래된 지시는 적용하지 않는다.
제출 후 실제 Actions와 공개 결과에서 stories=5/messages=1/target_met=true를 짧게 확인한다. sent/uncertain 잠금을 초기화하거나 같은 회차에 새 해시로 재발송하지 않는다. 조사/전송의 실제 시간과 검색량을 기록한다. 설정 저장·형식 검사·수집량은 실제 추천 품질/조회수 성과가 아니다.
사용자가 따로 즉시 보충을 요청한 때만 기존 version3 user_requested를 현재 실제 UTC hour로 사용한다. 지금 과거 보충을 반복하거나 별도 Telegram 운영 보고를 보내지 않는다.
