# BTP — 3시간마다 쓸 만한 10개
## 2026-10-24 최신 사용자 지시: 효율은 수량 축소 허가가 아니다
“10개 다 못 찾겠으면 사용량 더 써서 어떻게든 10개 보내긴 해야 될 거 아니냐. 효율적으로 하라는 거지 아무것도 안 보내도 괜찮다고 한 적 없다.”
10개는 완료 조건이다. 0~2개 현황 송신·수집 성공·형식 검사 성공으로 정기 회차를 완료하지 않는다.
이 문서는 아래 연결 문서와 과거 자동화 프롬프트의 고정 10분/검색6/열람24/검토20 상한, 0~9개 현황을 보내고 종료하라는 지시보다 우선한다.

## 기준은 어제 20시, 원본의 실제 포인트부터
[사용자가 긍정한 실제 10개 묶음](btp-reference-20261023-20.md), [원본 경로](btp-original-sources.md)를 읽고 편집 강도와 폭을 맞춘다. 개별 10개 전부의 영구 승인으로 해석하지 않는다.
축구 사건·놀림·돌발 대처, 3~5세대 여돌 자컨·예능·음방의 대사·자막·실수·티키타카, 밈·황당한 사건·정치 발언의 실제 포인트를 찾는다.
원본 장면·당사자 발언·실제 자료를 우선한다. 구체 행동·반전·모순·돈/권리의 이해관계가 확인되는 기사형 사실도 어제 20시 기준으로 비교한다.
검증 후보 중 상대 상위 10개를 고른다. 모두 초대형·100만 조회수 확실이어야 한다는 문턱으로 수량을 줄이지 않는다. 이름·외모·티저·일반 스코어·일반 경제지표로 억지 충원하지 않는다.

## 기본은 짧게, 부족하면 조사 예산 확대
한국시간 08·11·14·17·20·23시 클라우드에서 실행하며 실행 사이에는 종료한다. 매시간 기동·정각까지 대기·장시간 완료 감시는 하지 않는다.
첫 예산은 10분·검색6·열람24이며 종료 상한이 아니다. 10개가 부족하면 부족한 분야·사건·원본을 겨냥해 검색4·열람12 단위로 확장하고 필요한 만큼 후보를 추가 검토한다.
10개 확보를 위해 사용량을 늘리는 것은 최신 사용자 명시 승인이다. 처음 예산이 끝났다는 이유로 0~9개 현황을 제출하고 종료하지 않는다.
웹 도구의 본문 열기가 실패하면 동일 URL 반복 대신 접근 가능한 당사자 원문·방송사 자료·독립 보도로 전환한다. 공개 페이지의 표준 HTTP 확인은 가능하지만 보호·로그인·지역 제한을 우회하지 않는다.
같은 실패 URL 재열람, 검증 불가능한 영상 한 편을 붙잡기, 후보 3,000개 전체를 모델에 재입력하기, 과거 대화·대형 기록 반복 읽기, 테스트·환경 탐색에 예산을 낭비하지 않는다.
짧은 후보/예비 목록과 필요한 최근 7일 sent/uncertain 식별자를 도구 안에서 추린다. 유망 후보가 막히면 즉시 다른 원본·예비 후보·검색 범위로 전환한다.
검색/열람의 실제 누적량과 시간을 기록한다. coverage에는 실제 확인한 관련 자료를 기록하며 양식 때문에 실제 검토를 한 것처럼 꾸미지 않는다.

## 수집 실행
최신 main의 같은 checkout에서 `python run_discovery.py --min-refresh-seconds 480`를 한 번 실행한다. 의존성 준비→검사→같은 인터프리터 수집 순서를 유지한다. 수집 성공은 장면 검증이나 10개 확보가 아니다.
초기 수집이 정상인데 검증 소재가 부족하면 수집 재실행이 아니라 추가 원본 조사에 사용량을 쓴다. RSS404 경로 반복 금지. 표준 공개 채널/제작사 원문을 사용한다.
설치/수집의 90초/120초 프로세스 한도는 환경 장애 방지이며 AI 연구의 종료 상한이 아니다. 비밀값·암호화 state를 열람하지 않고 Telegram 자격 증명을 수집에 넘기지 않는다.

## 검증과 완료
최초 공개12시간·실제 검토75분·사건일/게시일 구분·사실/주장 구분·실제 장면/대사 확인을 유지한다. 검색 요약·썸네일·플레이어 로딩을 영상 시청으로 쓰거나 재기사 시각을 새 사건으로 바꾸지 않는다.
동일 사건과 최근7일 sent/uncertain 및 확인 가능한 실제 BTP 게재를 대조한다. 검증된 예비 후보도 준비해 중복을 빼고 실제10개를 채운다.
version2 검토본을 최신 receiver로 비송신 검사한다. production의 BTP_REQUIRE_TEN=1은 검토 단계와 최종 중복 제거 뒤 각각 10개 미달이면 exit3/needs_more_research로 반환한다. 0개 현황을 Telegram 성공이나 시간대 완료로 잠그지 않는다.
미달 응답이면 부족분을 계속 조사하여 보완한다. 새 검증 없이 verified_at만 고치지 않는다. 발송/불명확 전송 잠금과 이력을 초기화하지 않는다.
정기 제출은 기존 version2 request와 정확한 UTF-8+마지막 줄바꿈·SHA256·한 메시지·승인된 Python workflow를 유지한다. 미래 정각까지 대기하지 않는다.
제출 후 승인 Actions 결과와 공개 state의 실제 stories=10 및 전송 결과를 짧게 확인한다. 미달/실패를 성공으로 쓰지 말고 실제 실패 단계부터 복구한다. 이미 sent/uncertain인 메시지를 자동 재전송하지 않는다.
사용자가 명시적으로 요청한 이번17시 미달 보충은 기존 version3 user_requested 요청과 별도 user-curated 해시 키를 사용한다. 기존17시 정기 잠금은 보존하고 중복 검증을 유지한다. 연결 테스트나 과거 회차 몰아 보내기는 하지 않는다.
