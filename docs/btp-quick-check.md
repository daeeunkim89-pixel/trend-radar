# BTP — 3시간마다 강렬한 10개
2026-10-24 사용자 최종 확인: "찾은 거 중에 강렬한 거 10개를 세시간 마다 중복 없이". 수량은 줄이지 않고 장시간 실행과 불필요한 사용량을 줄인다. 과거 매시간 AI 조사·연속 대기보다 이 문서가 우선한다.

## 2026-10-24 사용자 보정 — 어제 20시 기준 우선
[실제 긍정 묶음](btp-reference-20261023-20.md)과 [검증된 원본 경로](btp-original-sources.md)를 먼저 읽는다.
원본의 실제 대사·행동·반전을 우선 찾고, 어제 묶음처럼 구체 사실·모순·이해관계가 확인된 소재 전체에서 상위 10개를 비교한다. “모두 대박 확실”이라는 절대 문턱으로 2~3개만 고르지 않는다.
짧은 목록 후보가 막히면 reserves 또는 다른 독립 원본으로 교체한다. 상세 검토 총 20개·열람 24개 한도는 유지하며 후보 목록 전체를 모델에 재입력하지 않는다.
원본 우선은 모든 기사형 소재의 금지가 아니다. 최신 사용자 “어제처럼 일단” 기준으로 제작 가능한 기사형 사실 소재도 비교한다. 기사 접근이 쉽다는 이유로 원본 탐색을 생략하지 않는다.
이미 발송한 기준 묶음의 사건은 반복하지 않는다. 기준 변경은 날짜·사실·실제 미디어·중복 보호의 해제가 아니다.

## 수집 실행 환경을 먼저 준비
클라우드 작업에서 원시 `python candidate_snapshot.py`를 바로 실행하지 않는다. 최신 main의 `run_discovery.py`, `requirements.txt`, 수집기와 가져오는 모듈을 같은 checkout에서 사용하고 `python run_discovery.py --min-refresh-seconds 480`을 한 번 실행한다. 이 진입점이 실제 인터프리터의 라이브러리를 확인하고, 없으면 격리 환경에 설치·재확인한 뒤 같은 인터프리터로 수집한다. 설치 후 수집을 생략하지 않는다. 최근 정상 수집이 있으면 기존 8분 중복 방지 조건으로 생략할 수 있다.
설치/실행 환경 실패(exit 2)는 '수집 성공·후보 0개'와 구별한다. 수집 성공도 원본·날짜·장면 검증이나 10개 선정을 보장하지 않는다. 설치·수집은 각 90초·120초 상한이며 Telegram 자격 증명은 수집 자식 프로세스에 넘기지 않는다. 대기·반복 재시도는 하지 않는다.

## 짧게 조사하고 종료
한국시간 08·11·14·17·20·23시마다 한 번만 점검한다. 실행 사이에는 종료한다. 매시간 조사·연속 대기·이전 회차 복구·완료 확인 반복을 하지 않는다.
회당 조사 10분 안에 종료하며 검색 최대 6개·원문/자료 열기 최대 24개·검토 후보 최대 20개다. 시간 제한은 AI 작업 지시이며 강제 종료 보장은 아니므로 호출 수 상한도 함께 지킨다. 승인된 송신 workflow는 10분에 종료한다.
이 문서와 기준 묶음·원본 경로, data/review-inbox.json, state/request를 먼저 읽는다. 대형 candidates/progress/history와 과거 대화 전체를 반복해 읽지 않는다. 유망 후보가 생기면 최근 7일 실제 sent/uncertain 이력에서 필요한 사건·URL·자료 식별자만 도구 안에서 추린다.
짧은 목록이 없거나 1시간 넘게 오래됐으면 직접 검색 예산 안에서 조사한다. 수집 완료·미래 정각·권한 응답을 기다리지 않는다. 차단된 경로를 반복하지 않는다.

## 강렬한 후보에서 10개 선정
축구 사건·놀림거리·돌발 행동, 3~5세대 여돌 자컨·음방·유튜브의 대사·자막·실수·대처, 밈·유머·황당한 사건·정치 발언/행동을 찾는다.
펨코는 편집 취향의 기준이지 재게시 수집 대상이 아니다. 구단·리그·방송사·아티스트/제작사 공식 콘텐츠·당사자 SNS에서 원본 공개 단계의 포인트를 먼저 찾는다. 펨코 게시·조회수 하한을 기다리지 않는다.
사용자 예시처럼 첫 장에 쓸 실제 대사·행동·모순·반전과 공유 이유가 선명한 순서로 상위 10개를 고른다. 평범한 스코어·기록·신곡 홍보·일반 경제지표·일반 해외 기사·큰 숫자로 숫자를 채우지 않는다. 모두 최상급이어야 한다는 조회수 예측 문턱도 만들지 않는다.
각 후보의 원본·최초 공개 12시간 이내·사건/게시 날짜·사실과 주장·실제 장면/대사·검토 75분을 확인한다. 못 본 영상·반응을 봤다고 쓰거나 재업로드를 새 사건으로 바꾸지 않는다.
발송 전 동일 사건과 최근 7일 sent/uncertain 및 실제 BTP 게재를 대조한다. 검증된 예비 최대 3개로 중복을 대체해 실제 10개를 준비한다. 원본·날짜·사실이 미확인된 소재로 채우지는 않는다. 실제 장애로 미달하면 정확한 수와 이유를 보고하고 10개 완료라고 쓰지 않는다.

## 발송 후 AI 종료
기존 edition version=2, request version=2, 정확한 UTF-8+마지막 줄바꿈과 SHA-256, 승인된 Btp 그룹·Python workflow를 유지한다. 기존 검증·동일 사건/7일 중복·시간대 잠금·불명확 전송 보호를 유지한다.
현재 정기 시간대에만 요청한다. 미래 정각 대기·같은 회차 요청 덮어쓰기·테스트·재시도 루프는 금지한다. picks/request 두 파일만 최신 main에 원자적으로 반영한다.
JSON은 하나의 정확한 문자열로 직렬화하고 그 바이트로 blob과 해시를 함께 만든다. 추가 줄바꿈이나 검토 시간만 바꾸어 검증한 척하지 않는다.
전달은 Actions가 처리하므로 AI는 실행 결과를 오래 기다리지 말고 종료한다. 코드 수정·별도 운영 요약·학습 문서 확장은 이 정기 점검에 포함하지 않는다. Telegram에는 제목·왜 올릴지·확인한 핵심 포인트·원본 링크를 간결히 한 메시지로 보낸다.
