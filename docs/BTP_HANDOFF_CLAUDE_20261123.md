## 3. 실제 실패와 사용자 평가
핵심 실패는 편집 적합성과 신뢰성이다. 설정 변경/단위테스트 통과가 이 문제를 해결했다는 증거는 아니다.

2. ChatGPT가 조사·선정본을 만들어야 GitHub 전송으로 넘어가는 구조다. ChatGPT 실행이 한도에 막히면 새 추천을 만들 수 없다. 같은 AI에게 “실패를 꼭 알리라”고 지시하는 것만으로 독립적인 실패 알림을 보장하지 못한다.
3. 최신 스포츠/시사 기사에 그럴듯한 선정 이유를 붙이는 방식으로 회귀했다. 세계대회 규모·확정 발표를 팬이 공유할 포인트와 혼동했다.

## 6. Claude로 옮길 때 반드시 알아야 할 호환성
현재제출계약은 ChatGPT producer를전제로 한다.
edition_preflight.py, curated_report.py, pin_report_request.py 등은 reviewer가 정확히 “ChatGPT”인입력을기대한다.
Claude가 검토한결과를 reviewer=ChatGPT로속여서통과시키면안된다. reviewer=Claude만입력하면현재코드가거부할수있다.
Claude/선택한producer를정직하게표시하도록검증규약·pinning·테스트·메타데이터를함께개선해야한다. 이인수인계에서그이전작업까지완료한것은아니다.

현행보호:
- REPORT_PICKS=10, REPORT_HOURS_KST=(9,). 09KST는UTC00이므로 hour_utc 예: YYYYMMDD00.
- v2최상위와pick필드는엄격한exact schema. 임의의새필드를그냥붙이면거부된다.
- 최초공개 published_at은실제원문시각. 예정09시기준24h범위. generated_at/verified_at검토유효기간75분.
- readiness.mode=scene 또는 major_news. scene은실제확인한영상/이미지와checked_materials가필요. 주요텍스트소식에무조건영상을강제하지않는다.
- 검토자료/원문은coverage.opened_urls와연결. 홈페이지URL을가져왔다는것만으로구체적사실·장면을확인한것이아니다.
- 현행v4요청: {"version":4,"hour_utc":"YYYYMMDD00","binding":"trigger_commit"}.
  picks/request를같은커밋에서함께변경해야하며 서버가불변입력의정확한바이트로해시를계산한다. 임의해시/따로커밋/실패회차덮어쓰기는피한다.
- GitHub sender만최대5분정시대기가능. AI가정시까지켜진채로기다리지않는다.
- BTP_REQUIRE_COMPLETE=1: 최종비공개중복제외뒤10개필요. 미달은needs_more_research이며전송완료가아니다.
- sent/uncertain·전송불확실 잠금은모델교체와무관하게유지한다. 응답불확실상태를성공/미송신으로단정해재전송하면중복위험이있다.
- Telegram토큰/ChatID는GitHub Secrets와기존런타임에서관리한다. 이문서에는값을포함하지않았다. 다른대화/Claude에기존연결권한이자동이전되지는않는다.
- AI공급자·클라우드런타임·사용량정책은Claude환경에서재설계/확인이필요하다. ChatGPT예약을끄고Claude대화를열기만한다고PC독립09시발송이성립하지않는다.

현행조사예산:
처음6검색/18본문 → 부족분2검색/7본문최대2회 → 마지막부족분4검색/12본문1회.
최대14검색/44본문이며10개완성즉시종료. 검색수와원문접근수가성과가아니다.
