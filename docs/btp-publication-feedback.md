# BTP 실제 게시 대조와 선정 학습 — 2026-11-15
성공 기준은 발송 개수가 아니라 사용자가 실제 BTP에 올릴 만한 추천을 받는 것이다. 기존 KST08/11/14/17/20시·10개·중복·검증 보호는 유지한다. 이 문서는 발송량을 편집 성과로 취급하는 과거 운영보다 우선한다.

## 매 회차의 연결
1. 선정 전에 bythepulse의 새 공개 게시물 또는 연결된 읽기 도구의 게시물·캡션·게시시각을 확인한다. 최초 대조는 최근30개/최근7일을 가능한 범위에서, 다음부터 새 게시물만 본다. 실제 Instagram 원본URL·post_id·관찰시각·읽은 범위·정확한 게시시각(없으면null)을 남긴다. 공개 접근은 먼저 시도하며 로그인 필수라고 추정하지 않는다. 막히면 회차당1회 상태만 기록하고 과거 링크·검색 변형·대형 과거 대화에 고착하지 않는다.
2. 실제 sent 이력의 동일 핵심 사실과 비교한다. 같은 선수·구단·분야라는 이유로 일치시키지 않는다. 새 반박·처분·계약·결과 등 다른 후속은 별개의 사실이다. 캡션/자료를 실제 읽어 동일 사실을 확인한 경우만 recommendation_matches에 기록한다.
3. 추천 후 게시 일치, BTP 선게시로 늦은 추천, 시각 미확인, 24시간 관찰 중, 완전 관찰 범위내 미일치, 관찰 불가를 구분한다. 게시 일치가 우리 추천을 보고 썼다는 증거는 아니다. 실제 직접 채택 확인이 없으면 직접 채택률은 null이다. 24시간 미일치도 영구 거절이라는 뜻이 아니다.
4. editorial_feedback.py가 실제 이력과 학습 기록에서 수치를 계산한다. 부분/차단 관찰을 미채택으로 세지 않으며 성숙한24h 코호트에 미확인이 남으면 게시일치율도null이다. 숫자를 말할 때 실제 분모·게시범위·관찰기간을 붙인다. 상위1~3순위가 실제로 게시됐는지도 별도로 본다.
5. 다음 검색·선정은 확인된 BTP 게시의 인물/독자 맥락·새 포인트·실제 자료·제목 각도와 대조한다. 그냥 큰 기사·최신 기사라는 이유로 통과시키지 않는다. 후보마다 'BTP 독자가 반응할 구체적 포인트 / 바로 쓸 수 있는 원본·장면·수치 / 왜 지금 / 실제 확인한 유사 BTP 사례 또는 아직 검증 안 된 가설'을 판단한다. 모든 스포츠를 해외 대회 규모만으로 재단하지 않는다. 유명 팀/선수의 새 직접 발언·반박·경기 반전이 BTP 독자에게 중요한지 근거로 비교한다. 일반 연예 제외라는 최신 사용자 범위는 유지한다.
6. 미반영 이유는 사실과 가설을 분리한다. 늦음은 실제 시각 선후가 있을 때 확인할 수 있다. 독자 관심 부적합·훅 약함·자료 부족·비슷한 소재 중복·게시 여력 등은 사용자 확인이 없는 한 가설이며, 사례를 붙여 다음 회차에서 검증한다. 미관찰이나 단1건으로 주제 전체를 자동 배제하지 않는다.
7. 10개 모두 게시 가치로 상대평가한다. 단순 수량 채우기를 금지하고 상위1~3개는 특히 바로 선택 가능한 수준의 사실·원본·제목 각도를 갖춘다. BTP에 이미 게시된 같은 사실은 재추천하지 않는다. 새로운 중대한 후속은 무엇이 바뀌었는지 명시한다.

## 기록 형태
기존 data/editorial-learning.json을 유지한다.
- profile_checks: at,profile_url,status,visible_post_ids,newly_documented_ids,limits. 실제 피드의 연속된 시간 구간을 완전히 읽었을 때만 complete_feed_window=true와 coverage_start_at/coverage_end_at, status=feed_observed를 쓴다. 부분 그리드·검색·로그인벽·이전 캐시는 완전 관찰이 아니다.
- observations: account=bythepulse,post_id,post_url,observed_at,published_at(정확히 모르면null),scope=caption/caption_and_media/connected_media,topic/짧은 관찰 요약. 표지밖에 안 봤으면 cover_only.
- recommendation_matches: [{event_key,same_fact_verified:true,evidence:"실제 캡션/자료에서 동일 새 사실을 확인한 짧은 근거"}]. 실제 읽지 않았으면 쓰지 않는다. 아직 추천되지 않은 BTP 사실은 동일 모양의 fact_identities로 기록하고 새 후보를 이 사실과 비교한다.
- observations의 reason/next_change는 확인된 사실과 검증할 가설을 표시한다. 오래된 rules는 역사적 기록이며 최신 사용자 지시와 충돌하면 적용하지 않는다.
- data/editorial-feedback.json은 자동 파생 보고서다. 직접 수치를 지어내지 않는다. 공개 게시/추천 정보만 저장하고 비공개 Insights나 로그인 비밀은 공개 저장소에 기록하지 않는다.
- 실제 전송 이력에는 앞으로 category/rank/source/published_at/why/angle/why_now도 보관한다. 옛 기록에 없던 값은 과거 사실처럼 채워 넣지 않는다.

## 저장과 운영
학습은 별도 data/editorial-learning.json 커밋으로 갱신한다. 파생 보고서는 학습 변경과 실제 발송 뒤 네트워크 없는 Python으로 갱신한다. picks/request의 두 파일 원자 제출 규칙과 sent/uncertain 잠금은 유지한다.
매 회차 먼저 파생 보고서 요약과 필요한 실제 사례만 읽고 이번 검색/선정 변경1~3개를 실제 근거와 함께 기록한다. 매일08시 최근7일의 확인 가능한 게시 일치·늦은 추천·놓친 BTP 소재·상위순위 적합성을 정리한다. Instagram 접근 실패를 근거로 취향 가중치를 바꾸지 않는다. 연결/공개 접근이 회복되지 않은 상태를 '모니터링 정상'으로 보고하지 않는다.
Instagram 점검 실패만으로 기존 뉴스 발송 예약을 끄지 않는다. 별도 운영 보고 Telegram·자동 게시·댓글·좋아요·추가 예약은 만들지 않는다.

## 확인된 공개 읽기 경로와 환경 구분 — 2026-11-15
사용자가 연 PC Edge 공개 프로필에서 새 post_id를 확인하고 공식 https://www.instagram.com/p/{shortcode}/embed/captioned/ 로 이동하면 일반 상세의 로그인 안내 없이 실제 캡션이 읽혔다. 이번에 최신12개를 읽어 학습 기록에 저장했다. URL 입력 직후 이전 문서가 남을 수 있으므로 실제 렌더링된 문서 URL/계정/캡션을 확인하고 기록한다. 프로필에서 신규 ID만 확인해 다음 회차에는 새 게시물만 읽는다. 로그인 안내·429·도구 차단 시 같은 경로 반복이나 우회는 하지 않는다.
이 성공은 사용자 PC의 Edge다. 앞서 클라우드 HTTP는429였으므로 PC 전원과 무관한 클라우드 모니터링 성공을 의미하지 않는다. 각 실행은 실행 환경과 성공 범위를 별도 기록한다. 본문 미확보 시 현재 접근 상태를 실패/미확인으로 남기고 기존 뉴스 발송은 유지한다.
[실제 12개 감사](btp-live-audit-20261115.md)의 관찰 표본 비교와 최근7일 추천 코호트 채택률을 구별한다. 관찰 게시물 중 추천 이력에 동일 사실이 없다는 수치는 놓친 게시 주제의 표본이며, 전체 추천이 거절됐다는 수치가 아니다.
