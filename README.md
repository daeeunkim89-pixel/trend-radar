# TREND RADAR — btp 텔레그램 소재함

## 발송 규칙

- **한국시간 매시 정각에 자동 보고서 1개만** 발송합니다.
- 매시 50분에 GitHub Actions에서 수집·분석을 시작해 다음 정각까지 기다립니다. GitHub 실행 대기·네트워크 때문에 00분 00초 도착을 보장하지는 못합니다.
- 준비가 정각 발송 허용 시간(20초)을 넘기면 해당 회차를 건너뜁니다. 지연된 보고서를 나중에 몰아서 보내지 않습니다.
- 같은 시간대의 보고서는 공통 전송 이력으로 중복을 막고, 자동 보고서가 여러 메시지로 나뉘면 전송을 거부합니다.
- 파일 수정·push·수동 검증으로 텔레그램 테스트 메시지를 보내지 않습니다. 일반 CLI 실행도 미리보기입니다.

## 짧은 보고서

첫 화면에는 btp 편집 기준에 따른 **우선 검토 5개**의 제목·출처·확인 가능한 반응만 표시합니다. 나머지는 텔레그램의 **펼쳐보기** 영역에 넣습니다. 사이트별 최대 10개 후보와 원문 링크는 모두 유지합니다. 같은 제목은 원문 링크를 보존해 묶습니다.

기본 보고서에는 긴 원문 발췌·추천 설명·이미지 URL·12자리 ID를 반복하지 않습니다. 전체 제목·짧은 원문 미리보기·btp 추천 근거·자료 링크는 상세 명령으로 확인합니다.

| 명령 | 동작 |
|---|---|
| `/info 03` | 3번 소재의 상세·자료 링크 |
| `/pick 03` | 선정 |
| `/hold 03` | 보류 |
| `/doing 03` | 제작 중 |
| `/done 03` | 업로드 완료 |
| `/clear 03` | 미선정 |
| `/queue` | 선정·보류·제작 목록 |
| `/help` | 사용법 |

번호는 최신 발송 보고서 기준입니다. 이전 보고서는 **해당 메시지에 답장하면서 명령과 번호를 입력**하면 그 보고서의 소재로 처리합니다. 기존 12자리 소재 ID 명령도 지원합니다. 다른 봇이 함께 있으면 `/pick@daeun_trend_radar_bot 03`처럼 봇 이름을 붙이세요.

명령은 약 10분 간격으로 점검하며 실행 대기로 지연될 수 있습니다. 상세·선정 응답은 사용자가 명령을 보냈을 때만 전송합니다. 사용자 이름·사용자 ID·대화 원문은 저장하지 않습니다.

## 수집·추천 기준

- 네이버 많이 본 뉴스 / 네이트 스포츠 / 디시 실베 / 펨코 포텐을 사이트별 최대 10개 수집합니다.
- 네이버는 언론사별 목록이며 통합 뉴스 순위가 아닙니다. 네이트는 스포츠 급상승 영역을 우선 읽고, 같은 순위 영역끼리만 순위 변화를 비교합니다. 디시는 PC·모바일 조회·추천을 읽고 공지·댓글 링크를 제외합니다.
- 같은 글의 직전 관측 대비 조회·추천 증가와 실제 관측 간격을 사용합니다. 첫 관측, 누락 지표, 감소한 누적 값, 5분 미만·6시간 초과 간격은 증가량 계산에서 제외합니다. 다른 사이트의 조회 수를 직접 비교하지 않습니다.
- 추천은 제목 속 축구·스포츠·문화·밈 등 편집 기준입니다. 계정 성과를 학습한 조회수 예측 모델이 아닙니다. 커뮤니티 주장은 기사·공식 발표로 대조해야 합니다.
- AI 요약·캡션·썸네일 문구 생성과 Instagram Insights는 연결되지 않았습니다. 원문 미리보기는 짧은 발췌이며 기사 게시 시각을 사건 발생일로 추정하지 않습니다.
- 펨코는 HTTP 430 보안 확인이 남아 복구되지 않았습니다. [진단과 접근 허용 문의](docs/fmkorea-access.md)를 참고하세요. 다른 정상 소스 보고는 계속합니다.

## 실행과 검증

- `Trend Radar`: 매시 50분 준비 → 다음 정각에 1개 발송. 예약 실행만 지원합니다.
- `Trend Radar preview (no Telegram)`: 수동 미리보기만 생성하며 봇 자격 증명과 전송 권한을 주지 않습니다.
- `Telegram connection check`: 수동으로 봇·그룹만 확인하며 테스트 메시지를 보내지 않습니다.
- `Btp editorial commands`: 매시 7·17·27·37·47·57분 사용자가 보낸 명령만 점검합니다.
- `Trend Radar validation`: 코드 변경 시 로컬 서버·Chromium 회귀 검증을 수행하며 텔레그램을 보내지 않습니다. 실제 펨코 연결 검사는 수동 실행에서만 추가 수행합니다.

```bash
pip install -r requirements.txt
playwright install --with-deps chromium
python monitor.py --preview
python monitor.py --commands-only
python monitor.py --check-fmkorea
python -m unittest discover -s tests -v
TREND_RADAR_BROWSER_TESTS=1 python -m unittest discover -s tests -v
```

운영용 Actions secrets는 기존 `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`를 사용합니다. 승인된 Btp 그룹 ID 해시도 확인합니다. 봇 토큰을 코드·로그에 넣지 마세요.

`data/history.json`은 공개 원문 메타데이터·관측 기록으로 최대 7일·5,000개 글, 글당 최근 24회 관측을 보관합니다. `data/state.json`에는 수집·전송 상태를 기록합니다. `data/editor.enc`에는 선정·번호 대응·수신 커서·전송 이력을 기존 봇 토큰과 그룹 설정에서 파생한 키로 인증 암호화합니다. 토큰·대상을 바꾸기 전에는 이전 키로 기록을 이관해야 하며 복호화 실패 시 파일을 덮어쓰지 않고 중단합니다.

소스 오류가 있어도 정상 소스 보고·상태 저장은 마친 뒤 종료 코드 1을 반환합니다. 따라서 펨코 실패 때문에 Actions가 실패로 표시되어도 다른 소스 전송은 성공할 수 있습니다.
