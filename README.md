# TREND RADAR — 폰만으로 설치

현재 코드는 네이버 많이 본 뉴스 / 네이트 스포츠 / 디시 실베 / 펨코 포텐을 매시간 수집해 각 소스에서 최대 10개를 텔레그램으로 보냅니다. 글별 기록으로 직전 관측 대비 조회·추천 증가를 비교하고 동일 제목을 묶어 btp 편집 적합도 순서로 전부 전송합니다. 소스별 목록 위치는 통합 인기 순위가 아닙니다.

네이트는 확인 가능한 스포츠 급상승 순위 영역을 우선 사용하며 해당 영역을 확인하지 못하면 스포츠 목록으로 표시합니다. 같은 순위 영역이 확인된 관측끼리만 순위 변화를 비교합니다. 디시는 PC·모바일 목록에서 제목과 조회·추천 수치를 읽고 공지·댓글 링크를 제외합니다.

## 준비물
- GitHub 계정
- Telegram 계정

## 1. 텔레그램 봇 만들기
1. Telegram에서 `@BotFather` 검색
2. `/newbot` 입력 → 봇 이름/아이디 지정
3. 발급되는 Bot Token 복사
4. 만든 봇에게 아무 메시지나 한 번 보내기
5. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates`를 열어 `chat.id` 숫자를 확인

여러 사람이 같이 받으려면 텔레그램 채널/그룹을 만들고 봇을 추가한 뒤 해당 채널/그룹의 chat id를 사용하세요.

## 2. GitHub에 올리기
1. GitHub에서 새 Repository 생성 (가능하면 Private)
2. 이 ZIP의 내용 전체를 저장소 루트에 업로드
3. 저장소 `Settings → Secrets and variables → Actions`
4. Repository secrets에 다음 2개 생성
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`

## 3. 실행
`Actions → Trend Radar → Run workflow`를 눌러 즉시 수집하고 TOP 10을 전송할 수 있습니다.
그 뒤 매시간 예약 실행이 작동합니다. `data/state.json`에는 최신 수집 수, 전체 상태(`ok`/`degraded`), 소스별 오류가 저장됩니다.

## 중요
현재 예약은 `0 * * * *`입니다. GitHub Actions가 혼잡하면 실행이 지연될 수 있습니다. 또한 각 사이트의 HTML 구조/접근 정책이 바뀌면 해당 파서를 수정해야 합니다. 확인할 수 없는 조회·추천 수치는 만들어내지 않습니다.

## 펨코 수집 진단

텔레그램을 보내거나 운영 상태 파일을 변경하지 않고 검사하려면:

```bash
pip install -r requirements.txt
playwright install --with-deps chromium
python monitor.py --check-fmkorea
```

`Actions → Trend Radar validation → Run workflow`에서도 동일한 검사와 회귀 테스트를 실행할 수 있습니다. 관련 코드 변경 시 로컬 서버를 이용한 회귀 테스트가 자동 실행되고, 실제 펨코 연결 검사는 수동 워크플로 실행에서만 추가로 수행합니다.

초기 HTTP 430 뒤 정상 페이지로 이동하는 경우에는 실제 게시물이 나타날 때까지 기다립니다. 보안 화면의 “비정상 접속이 의심되어 차단” 문구가 계속 나타나면 접근 차단으로 기록하며 정상 수집으로 처리하지 않습니다. 이 경우 현재 실행 환경의 접근 허용 여부를 확인해야 하며, 코드 수정만으로 차단 해제를 보장할 수 없습니다. 접근이 허용된 실행 환경 또는 사이트 측 접근 허용이 필요합니다.

2026-10-14 GitHub 실행 검사에서 브라우저를 기다린 뒤에도 PC·모바일 모두 HTTP 430과 “사람인지 확인” 보안 화면이 남았습니다. 자동 수집 복구는 아직 확인되지 않았으며, 해당 상태는 수집 실패로 기록됩니다.

소스 수집에 실패하면 정상 수집한 소스의 보고와 상태 저장을 마친 뒤 종료 코드 1을 반환합니다. 시간별 워크플로는 실패 상태에서도 최신 진단을 저장하므로 Actions의 녹색 성공만 보고 수집이 정상이라고 판단하지 않게 됩니다.

회귀 테스트:

```bash
python -m unittest discover -s tests -v
TREND_RADAR_BROWSER_TESTS=1 python -m unittest discover -s tests -v
```

두 번째 명령은 Chromium 설치 후 실행하며, 로컬 HTTP 서버로 430 후 복구·지속 차단·빈 목록을 검사합니다. 실제 펨코 연결 여부는 별도의 수집 검사 결과로 확인합니다.


## btp 소재함과 선정 명령

소재마다 제목·원문·첫 포착 시각, 추출 가능한 짧은 원문 미리보기·기사에 표시된 게시 시각·미리보기 이미지·영상 링크, btp 추천 근거, 확인된 반응 변화를 제공합니다. 전문·영상을 복제하지 않으며 추출할 수 없으면 확인 불가로 표시합니다. 기사 게시 시각을 사건 발생일로 추정하지 않습니다.

추천은 제목 속 축구·스포츠·문화·밈 키워드와 기록·예상 밖 상황 등 편집 기준을 사용합니다. 계정 성과를 학습한 조회수 예측 모델이 아닙니다. AI API는 연결되지 않았고, 원문 미리보기는 짧은 발췌입니다. 자동 캡션·썸네일 문구, Instagram Insights, 다른 제목의 동일 사건에 대한 의미 분석·자동 사실 검증은 후속 연동 범위입니다. 커뮤니티 글은 기사·공식 발표로 확인해야 합니다.

각 소재 하단의 12자리 ID를 사용합니다. 다른 봇이 함께 있으면 `/pick@daeun_trend_radar_bot ID`처럼 봇 이름을 붙이세요.

| 명령 | 동작 |
|---|---|
| `/pick ID` | 선정 |
| `/hold ID` | 보류 |
| `/doing ID` | 제작 중 |
| `/done ID` | 업로드 완료 |
| `/clear ID` | 미선정 |
| `/queue` | 선정·보류·제작 목록과 링크 |
| `/help` | 사용법 |

명령은 `Btp editorial commands`가 매시 7·17·27·37·47·57분에 점검합니다. 즉시 응답하는 버튼형 봇은 아니며 Actions 혼잡·대기 때문에 지연될 수 있습니다. 다음 보고서에도 상태가 표시되고 업로드 완료 소재는 뒤로 보냅니다. 최초 연결 시 기존 메시지는 처리하지 않고 이후 명령부터 받습니다. 설정된 그룹의 사람 명령만 처리하며 사용자 이름·사용자 ID·대화 원문을 저장하지 않습니다.

## 기록과 전송

- `data/history.json`: 공개 원문 메타데이터·관측 기록. 최대 7일·5,000개 글, 글당 최근 24회이며 먼저 도달한 제한이 적용됩니다.
- 첫 수집은 비교 기준만 만듭니다. 5분 미만·6시간 초과 관측 간격, 누락 지표, 감소한 누적 수치는 증가량 계산에서 제외합니다. 실제 관측 간격을 표시하고 증가 속도는 같은 소스의 확인된 조회 지표끼리만 비교합니다.
- `data/editor.enc`: 선정 상태·수신 커서·전송 이력을 기존 봇 토큰과 대상 그룹에서 파생한 키로 인증 암호화합니다. 공개 저장소에 선정 상태를 평문으로 남기지 않습니다. **봇 토큰·전송 대상을 바꾸기 전 이전 키로 기록을 이관해야 합니다.** 복호화 실패 시 파일을 지우거나 덮어쓰지 않고 중단합니다.
- 운영·수동 보고·명령 워크플로는 같은 실행 잠금을 사용하고 대기 후 main의 최신 상태를 읽습니다.
- Telegram API의 HTTP 상태·`ok`·반환 그룹 ID를 확인합니다. 그룹 전송 간격과 짧은 429 `retry_after`를 반영합니다. 확인된 전송을 기록해 재실행 중복을 줄입니다. 네트워크 오류로 전송 결과가 불명확하면 해당 보고서의 자동 재전송을 중단합니다.
- 기존 두 Actions secret을 사용하며 승인된 Btp 그룹 ID 해시도 확인합니다. 새로운 비밀 설정은 필요하지 않습니다.
- `python monitor.py --commands-only`는 명령만 점검하고, `--force-report`는 같은 시간대에도 별도 보고서를 보냅니다.
- `Trend Radar one-time report`는 수동 실행과 해당 워크플로 파일 변경 시 한 번 실행되고, 수집 기록·암호화 상태도 저장합니다.
