# TREND RADAR — BTP 소재 선발굴·3시간 보고

BTP(@bythepulse)에 지금 올릴 만한 소재를 **ChatGPT가 매시간 웹에서 조사하고 원문을 검토해 선정**합니다. GitHub의 Python 워크플로는 그 결과를 검증하고 기존 승인된 Btp 그룹에 시간대당 메시지 한 개로 전달합니다.

## 현재 운영

1. `Trend Radar` 예약 수집은 공개 커뮤니티·뉴스 목록과 본문의 자료 링크를 `data/candidates.json`에 모읍니다. 이 단계에는 Telegram 자격 증명이 없으며 발송하지 않습니다.
2. 기존 ChatGPT 작업이 매시간 펨코 취향에 맞는 국내·해외축구 사건·놀림거리, 3~5세대 여자아이돌 콘텐츠·음방 화제, 일반 밈·유머·정치·시사를 조사합니다. 원본 공개 단계에서 먼저 찾고 실제 자료를 검토해 **08·11·14·17·20·23시 추천 10개**와 검증된 예비 최대 3개를 준비합니다. 100만 조회수는 편집 목표이며 달성 보장이나 추정 조회수로 표시하지 않습니다.
3. `data/editorial-picks.json`과 그 정확한 바이트 해시가 담긴 `data/report-request.json`을 같은 커밋으로 등록합니다. 코드 변경·일반 상태 저장은 발송 트리거가 아닙니다.
4. `Trend Radar delivery request`가 트리거 커밋에서 두 파일을 고정해 읽고 `curated_report.py`로 전달합니다. 보고 정각 전 60분 이내에 준비된 보고서는 정각까지 기다립니다. 지연되면 현재 시간대만 대상으로 하며 지난 보고서를 몰아서 보내지 않습니다.
5. 수집량이나 단어 점수만으로 만든 보고서는 자동 발송하지 않습니다. 검토본이 없거나 잘못됐으면 검증 단계에서 중단합니다. 중복 제거 후 검토된 상위 10개를 한 메시지로 보내며, 예비 후보까지 조사했는데도 10개에 못 미치면 실제 수와 부족한 이유를 명시합니다. 제목·선정 이유·첫 장 구성을 짧게 보여 주고 전체 검증·자료는 `/info`에 보존합니다.
6. 새 검토본은 버전 2로, **직접 확인한 핵심 장면 또는 확정된 큰 영향 / 실제 사건·발표 날짜 / 2~4장 제작 순서**가 필수입니다. 장면 추천에 실제로 확인한 이미지·영상이 없으면 거절합니다. `/info` 한 화면에서 이 내용과 원본 자료를 함께 볼 수 있습니다. 이는 검토 기록의 요건이며 조회수 예측 모델이 아닙니다.

GitHub 및 ChatGPT 실행 시각은 지연·누락될 수 있어 정확한 정각 도착을 보장할 수 없습니다. 정각 전 접수는 대기 상태이며 실제 전달 결과는 state/status/history와 전달 로그로 확인합니다. 발송은 기존 공통 시간대 이력으로 한 번만 처리하고, 결과가 불명확하면 자동 재전송하지 않습니다.

## 무엇을 추천하는가

2026-10-22 사용자 재설정에 따라 **펨코에 올라올 만한 소재를 원본 단계에서 선발굴**합니다. 펨코에 이미 게시됐는지와 조회수는 통과 조건이 아닙니다.

- 국내·해외축구의 사건사고, 라이벌 놀림거리, 실수·돌발 행동·반응·직접 발언과 화제 장면.
- 3~5세대 여자아이돌의 YouTube·자체 콘텐츠·예능·음방·앙코르·직캠에서 나온 실제 대화·실수·대처·반전과 확인된 사건.
- 일반 커뮤니티에서 공유될 밈·유머·황당한 사건·생활 공감·정치 발언/행동·시사 쟁점. 메이저 스포츠도 같은 구체적 포인트가 있을 때 함께 비교합니다.

세 갈래를 모두 탐색한 뒤 검증 후보 전체에서 상위 10개를 고릅니다. 고정 장르 할당이나 “100만 조회수 확실” 문턱을 두지 않습니다. 각 추천은 실제 원본과 최초 공개 시각, 누구에게 무엇 때문에 공유할지, 확인한 대사·동작·결과로 만든 구체적인 첫 장과 후속 컷을 갖춥니다.

[최신 선정 기준·운영 절차·JSON 스키마](docs/btp-editorial.md)와 [사용자 취향·과거 공개 표지 관찰](docs/btp-profile.md)을 따릅니다. 과거 표지 관찰과 실제 성과 분석은 구별합니다.

## 수집 범위와 한계

자동 발견 경로는 네이버 많이 본 뉴스, 네이트 스포츠·연예·축구, 디시 실베, 더쿠 HOT, 개드립 인기, 루리웹 베스트, 보배드림 베스트, 인스티즈 이슈, 엠팍 BEST, 펨코 및 공개 간접 목록입니다. ChatGPT는 여기에 한국어·영어 웹 검색, 원본 X/YouTube/Instagram 게시물, 구단·대회·아티스트 등의 공식 발표를 함께 조사합니다. 인터넷 전체의 누락 없는 수집을 보장하는 기능은 아닙니다.

펨코 직접 접속의 HTTP 430은 미해결입니다. 이슈링크의 펨코·전체 공개 목록과 LL 공개 피드, 다른 커뮤니티 본문에 명시된 펨코 출처로 발견 경로를 보완합니다. 갱신이 느리거나 막힌 경로는 표시하고, 열지 못한 원문을 읽었다고 기록하지 않습니다. 목록 시각·외부 수집 시각·실제 사건 발생일을 구분하며 간접 목록의 점수를 현재 펨코 조회·추천 수로 바꾸지 않습니다. [접속 진단](docs/fmkorea-access.md).

Instagram 공개 게시물의 좋아요·댓글은 확인 가능한 범위에서만 씁니다. 저장·공유·도달·유지율·Insights는 연결되지 않았으며, Threads 수치를 Instagram 성과로 사용하지 않습니다. Python 내부에서 LLM API를 호출하는 방식은 아니며 기존 ChatGPT 작업이 실제 웹 조사와 편집 판단을 담당합니다.

## 중복·선정 관리

- 자동 보고서는 시간대당 1개·메시지 1개입니다. 정기 준비와 누락 복구가 같은 암호화 이력을 사용합니다.
- 이전 7일의 발송·부분 전송·결과 불명확 소재를 URL·게시물 ID·정규화 제목·확인된 미디어와 원본 링크·편집 사건 ID로 비교합니다. 제목이나 사이트가 달라져도 동일 사건은 제외합니다.
- ChatGPT도 공개된 최근 결정과 BTP의 기존 게시물을 확인합니다. 과거 보도에 중요한 새 사실이 생기면 그 변화와 출처를 명시합니다. 계정 전체 게시 이력이 공개되지 않는 경우 그 한계를 감추지 않습니다.
- `/info 1`은 추천 이유·최신성 근거·검증 출처·제작 각도·자료를 보여 줍니다. `/pick 1`, `/hold 소재ID`, `/doing 소재ID`, `/done 소재ID`, `/clear 소재ID`, `/queue`를 유지합니다. 이전 보고서의 번호는 해당 메시지에 답장해서 사용합니다.
- 명령은 별도 `Btp editorial commands` 실행에서 약 10분 간격으로 처리하며 지연될 수 있습니다. 사용자 이름·수신 대화 원문은 저장하지 않습니다.

## 검증

```bash
pip install -r requirements.txt
playwright install --with-deps chromium
python candidate_snapshot.py
python monitor.py --preview
python curated_report.py --preview --hour YYYYMMDDHH --picks-file data/editorial-picks.json
python fmkorea_indirect.py
python -m unittest discover -s tests -v
TREND_RADAR_BROWSER_TESTS=1 python -m unittest discover -s tests -v
```

`monitor.py --preview`는 기존 수집 규칙의 진단용 미리보기이며 실제 편집장 선정본과 구분합니다. 코드 검증·미리보기·연결 확인은 테스트 메시지를 보내지 않습니다.

운영 워크플로는 기존 `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID` secrets와 승인된 그룹 ID 해시를 사용합니다. 에이전트는 토큰·Chat ID 값·암호화된 상태 내용을 읽거나 출력하지 않습니다. `data/editor.enc`는 기존 키로 인증 암호화하며, 복호화가 실패하면 덮어쓰지 않습니다. Instagram에는 자동 게시하지 않습니다.

`data/history.json`은 공개 원문 관측 기록(7일·최대 5,000개), `data/candidates.json`은 최신 공개 발견 입력, `data/editorial-picks.json`은 검토본과 공개 출처, `data/state.json`은 실제 발송 결과와 공개 추천 목록입니다.
